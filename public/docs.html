Accepter des paiements avec Pay243

Une seule intégration pour encaisser vos clients en RDC par wallet Pay243, M-Pesa, Airtel Money, Orange Money et cartes Visa/Mastercard, en CDF ou en USD.

1. Principe

  1. Votre serveur crée un paiement avec votre clé secrète sk_test_… / sk_live_….
  2. Vous redirigez le client vers checkout_url (page de paiement hébergée par Pay243).
  3. Le client paie avec le moyen de son choix ; il est renvoyé vers votre return_url?payment_id=….
  4. Pay243 vous notifie par webhook signé payment.succeeded : c'est le signal pour livrer.

Les montants sont des entiers en unités mineures : 2500 en USD = 25,00 $ ; 2500000 en CDF = 25 000 FC.

2. Authentification

Authorization: Bearer sk_test_VOTRE_CLE_SECRETE
Idempotency-Key: 6f1c…   (recommandé sur tous les POST)

La clé secrète ne doit jamais apparaître dans une application mobile ou du JavaScript navigateur.

3. Créer un paiement

POST /v1/payments

curl -X POST $BASE/v1/payments \
  -H "Authorization: Bearer $SK" -H "Content-Type: application/json" \
  -H "Idempotency-Key: CMD-1024" \
  -d '{
    "amount": 4500,
    "currency": "USD",
    "description": "Commande #1024",
    "reference": "CMD-1024",
    "return_url": "https://maboutique.cd/merci",
    "cancel_url": "https://maboutique.cd/panier",
    "metadata": { "client_id": "778" }
  }'
{
  "id": "pay_9xG…", "object": "payment", "status": "requires_payment",
  "amount": 4500, "currency": "USD", "fee": 0, "net": null,
  "checkout_url": "https://pay243.com/checkout/pay_9xG…",
  "expires_at": "2026-11-10T16:00:00.000Z", …
}
ParamètreDescription
amount*Entier > 0, unités mineures
currency*CDF ou USD
descriptionAffiché au client (200 car.)
referenceVotre identifiant de commande (filtrable)
return_url / cancel_urlURLs de retour
expires_in_minutesDéfaut 60, min 5, max 10080
metadataObjet libre (20 clés max.), renvoyé dans les webhooks

4. Autres endpoints

GET/v1/payments/:idStatut d'un paiement
GET/v1/payments?status=succeeded&reference=CMD-1024&limit=20Liste
POST/v1/payments/:id/cancelAnnule un paiement non payé
POST/v1/payments/:id/refunds { amount?, reason? }Remboursement total ou partiel (vers le wallet, la carte ou le numéro Mobile Money d'origine)
GET/v1/balanceSolde disponible CDF / USD
POST/v1/payouts { amount, currency, phone, operator? }Versement de votre solde vers Mobile Money
GET/v1/eventsJournal des webhooks et de leurs livraisons

5. Statuts d'un paiement

requires_paymentEn attente du client (ou dernier essai échoué : voir last_error)
processingDemande Mobile Money envoyée, le client doit valider avec son PIN opérateur
succeededPayé — net = amount − fee crédité sur votre solde
partially_refunded / refundedRemboursé en partie / en totalité
canceled / expiredAnnulé par vous / lien expiré

6. Webhooks

Événements : payment.succeeded, payment.failed, payment.refunded, payment.canceled, refund.failed, payout.succeeded, payout.failed. Réessais automatiques avec délai exponentiel (8 tentatives) tant que vous ne répondez pas 2xx.

Pay243-Signature: t=1762790400,v1=5f2c…   // HMAC-SHA256(webhook_secret, t + "." + corps_brut)
// Node.js (SDK fourni : sdk/node/pay243.js)
app.post('/webhooks/pay243', express.raw({ type: 'application/json' }), (req, res) => {
  const event = Pay243.webhooks.constructEvent(req.body, req.get('Pay243-Signature'), process.env.WHSEC);
  if (event.type === 'payment.succeeded') livrerCommande(event.data.reference);
  res.sendStatus(200);
});
<?php // PHP
$payload = file_get_contents('php://input');
parse_str(str_replace(',', '&', $_SERVER['HTTP_PAY243_SIGNATURE']), $sig);
$expected = hash_hmac('sha256', $sig['t'] . '.' . $payload, getenv('WHSEC'));
if (!hash_equals($expected, $sig['v1']) || abs(time() - (int)$sig['t']) > 300) { http_response_code(400); exit; }

7. Bouton de paiement (navigateur)

<script src="https://pay243.com/sdk/pay243.js"></script>
<div id="payer"></div>
<script>
  Pay243.button('#payer', {
    createPayment: () => fetch('/api/commande', { method: 'POST' }).then(r => r.json()) // votre serveur
  });
</script>

Sans développement : créez un lien de paiement depuis l'espace marchand et partagez-le par WhatsApp ou SMS.

8. Erreurs

{ "error": { "code": "insufficient_funds", "message": "Solde insuffisant." } }

Codes HTTP : 400 requête invalide · 401 clé/session invalide · 402 fonds insuffisants ou carte refusée · 403 plafond KYC · 404 introuvable · 409 état incompatible · 410 expiré · 429 trop de requêtes · 502 opérateur indisponible.
